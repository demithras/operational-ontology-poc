Operational Ontology Lab

A falsifiable local proof-of-concept: can a small, open-source operational ontology drive a real operational decision, gate it before any external effect, observe the real outcome, and replay the decision months later? And is any of that worth its cost over a simpler baseline?

Bottom line

Works

The machinery works. Governed decisions, hard gates, durable actions, replay across contract evolution, bounded agents: all supported in Round 1 (13 of 14 hypotheses) and again as a generic engine in Round 2.

Not shown

The value claim has not been shown. Three times the question was asked a different way, and each time an equally strong conventional build matched it at lower cost.

Open

One comparative question is still open: does the ontology control plane contain a compromise better than a conventional one (H30, not run)?

      Round 4: agent operations (frozen, not run)
      
  
      Round 4 moves from manufacturing to agent-run IT work. It asks whether the decision → authorization → policy → approval → action → observed outcome pattern, plus Round 3 containment, helps AI agents that work across several repositories. It covers coordination (who works on what) and control (what an agent may do, with the outcome confirmed from GitHub, CI or deploy, not from the agent). It runs on a relational store and is staged. Stage 1, the pilot, gates merge_pr and tests H31–H35. Stage 2 (H37, access grants) runs only if at least one of H31–H35 is supported; otherwise the round stops after stage 1 and H37 is recorded as not run, never rejected. The protocol was frozen on 2026-10-28 (round4/); no Round 4 evidence exists yet.
      
  
        
    
      • H31Do leases catch double claims and stale claims? Baseline to beat: bd ready + GitHub assignees.
        • 
    
      • H32Are cross-repo blockers surfaced before an agent spends a run? Baseline to beat: beads dependencies inside each repo.
        • 
    
      • H33Does the control gate contain an adversarial agent? Baseline to beat: branch protection + CODEOWNERS + required checks.
        • 
    
      • H34Do items close only on an independently observed outcome, so a false "done" is caught? Baseline to beat: agent self-report + human spot check.
        • 
    
      • H35Is "why did this merge or deploy happen" answerable months later? Baseline to beat: GitHub audit log + PR timeline + bead history.
        • 
    
      • H37Stage 2, triggered. Do agent access grants stay least-privilege, expire and really revoke? Baseline to beat: Vault dynamic credentials + IAM conditions + JIT access.
        • 
    
      • H36Do the gains outweigh setup and maintenance cost? Parity counts as REJECTED. Baseline to beat: the whole conventional stack.
        • 
  
      
  
      Headroom rule: a +20-point bar applies while the baseline succeeds at most 80% of the time; above that the treatment must close half of the baseline's misses; at 95% or more the class is recorded as CEILING (no advantage measured), never REJECTED. This is the lesson of Round 3's ceiling effect.
