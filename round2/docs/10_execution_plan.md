# 10 — Execution plan: kill-chain, not feature roadmap

## Gate 0 — freeze independent IR

Before H15, finalize `ontology/ir.schema.json`, semantic-equivalence rules and baseline DSL. OpenPona must not define its own oracle.

## Gate 1 — H15

Build only enough parser/compiler/renderer to attack OpenPona lossless expressivity. Do **not** build a full Engine merely to rescue the language.

If H15 is rejected, continue with a simpler typed Ontology Language candidate; preserve OpenPona as a human/agent layer. Do not stop EOO research solely because OpenPona fails.

## Gate 2 — H16 + H17

Test bounded kernel and hard Function/Action separation before self-hosting.

## Gate 3 — H18 + H19

Make the project itself Domain 2, under Git authority. Dogfood real hypotheses/evidence, not toy project objects.

## Gate 4 — H20

Remove/forbid domain-specific Engine branches. Execute both domains through generic runtime contracts.

## Gate 5 — H21

Generate typed SDK/query/action/agent surfaces. A handwritten endpoint for every new object/action is a failure of the Toolchain claim.

## Gate 6 — H22

Only after D3+ real domains exist should the project make a strong semantic-variety/break-even claim.
