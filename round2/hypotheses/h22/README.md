# H22 — Semantic-variety reuse eventually repays ontology-specific tax

## Claim

Across at least three independently useful real domains, the shared Ontology Language/Engine/Toolchain reduces marginal adaptation effort for blind semantic changes/tasks enough to create a stable advantage over a strong conventional typed relational/event baseline without correctness or security regression.

## Strong null/rival

Any local reuse is too small or rare to repay ontology-specific infrastructure, compiler, governance and cognitive tax; a conventional typed architecture scales equally well or better.

## Why this exists

A bounded meta-model plus reusable Engine/Toolchain should amortize common integration/governance/query/action machinery as semantic variety rises, flattening marginal domain/change cost.

## Primary falsifiers

- With N>=3 real domains, adaptation-cost slopes remain equivalent or favor baseline across preregistered task classes.
- Savings disappear when equivalent code generation/caching/security tooling is provided to baseline.
- Any material savings require sacrificing correctness, replay, security or maintainability.
- Benefits occur only in synthetic benchmark cases outside declared realistic workload tiers.

## Python Hypothesis role

Generate adversarial variants of declared task shapes and source/schema mutations to broaden coverage; do not use synthetic property tests as the final real-domain trend evidence.

## Stop rule

- Do not issue SUPPORTED/REJECTED trend verdict with fewer than three real domains; emit INCONCLUSIVE and wait for genuine domain evidence.
