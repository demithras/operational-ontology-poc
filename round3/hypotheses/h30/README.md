# H30 — Paladin security premium creates measurable operational value over a strong conventional baseline

## Claim

Across blind realistic adversarial workloads, the Paladin EOO control plane produces a materially better operational-security trade-off than an equally competent conventional typed/event architecture: lower blast radius and/or faster containment/recovery in multiple independent attack classes, with no safety regression and with the recurring/latency premium bounded by preregistered limits.

## Strong null / rival

Once the conventional baseline receives equivalent zero-trust authorization, typed schemas, generated tools, provenance integrity, reconciliation, retries and security engineering, Paladin provides no material security advantage; it is mostly additional machinery and cost.

## Mechanism under test

A single executable semantic contract jointly derives least-capability surfaces, authority topology, effect governance, disclosure boundaries, provenance bindings, external reconciliation and recovery semantics, reducing the number of inconsistent security decisions and limiting compromise propagation.

## Primary falsifiers

- All preregistered security outcomes are at parity or favor the baseline after equivalent hardening.
- Any apparent advantage disappears when the baseline receives an obvious equivalent control.
- Paladin has a safety regression in any attack class.
- Security gains require violating the frozen latency, recurring-complexity or safe-progress premium limits.
- Advantages occur only on synthetic cases outside the declared realistic workload tier.

## Experiment

Blind A/B adversarial comparison using the same attack intents, ground-truth oracles and operational workload against frozen Paladin and strong conventional variants.

1. Freeze both variants, fairness rules, threat classes and measurement scripts before revealing blind tasks.
2. Build the baseline with equivalent best-practice controls; shared low-level libraries are allowed and preferred when they remove implementation-quality confounds.
3. Reveal at least 40 blind tasks across at least five attack classes, including realistic multi-step incidents and recovery.
4. Measure forbidden effects, affected resources/effects (blast radius), containment steps/time, recovery correctness/operator actions, safe progress, p95 latency and recurring security-specific LOC/components.
5. Run identical correctness/security ground-truth oracles against both variants.
6. Report a Pareto trade-off frontier and per-class ratios; do not collapse security and cost into a single weighted winner score.

## Independent oracle

Per-task independent effect/authority/disclosure/provenance/recovery oracle plus external ground-truth effect stores and frozen cost/latency measurement scripts.

## Fair baseline

Strong conventional typed relational/event architecture with equivalent zero-trust identity/authorization, policy engine, typed schemas/codegen, least-privilege service credentials, append-only/content-addressed provenance, reconciliation, idempotency, retries, observability and recovery engineering.

## Stop rule

- If H23-H29 work but H30 rejects, retain any independently useful mechanisms but abandon the claim that a Paladin EOO control plane is justified as a superior security architecture in the tested regime.
