# 00 — Research posture

Round 3 asks whether the architecture earns a **Paladin** identity through measurable behavior, not naming or armor-by-checklist.

The central attractor remains:

> Discover the minimal architecture of an operational ontology/control plane, then build an open-source implementation of it.

Round 2 falsified a broad efficiency mechanism: ontology-specific reuse did not repay its tax merely as semantic variety increased. Round 3 is allowed to falsify the Paladin thesis as well.

## Strong null

An equally competent conventional typed/event architecture with modern zero-trust controls can achieve the same operational security and resilience more simply. If that null survives fair attack, the project should extract any useful generic mechanisms and narrow or abandon the stronger Paladin-EOO claim.

## No security theater

Certifications, cryptography, policy engines, ontologies, signed artifacts and generated tools are mechanisms. None count as value until the relevant adversarial hypothesis survives an independent oracle and fair baseline.
