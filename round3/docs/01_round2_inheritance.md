# 01 — What Round 3 inherits from Round 2

Pinned upstream: `protocol/UPSTREAM_EVIDENCE.json`.

Round 3 treats the following as prior supported capabilities within their tested scope:

- a bounded generic kernel can serve semantically different domains;
- Function and Action can be a hard runtime effect boundary;
- Git can remain canonical while executable state rebuilds deterministically;
- one generic Engine can execute multiple domains without domain branches;
- a typed capability-aware Toolchain can be generated from the contract.

It also inherits two negative facts:

- Project Ontology did not beat a strong file/Git baseline on the original H18 value claim;
- H22/H22w rejected the idea that semantic-variety reuse alone repays ontology-specific tax.

Therefore Round 3 must not use "the machinery works" as evidence that "the machinery is worth it." H30 exists specifically to answer the new value mechanism.
